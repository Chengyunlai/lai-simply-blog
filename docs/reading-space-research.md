# 把首页设计成一间“阅读室”：研究笔记

**目的**：为个人技术文章 / 开源项目首页建立可执行的空间、版式与色彩依据。这里的“室内”是叙事隐喻，不是把页面装饰成真实房间：用户应该依次经历入口、主墙、阅读桌与书架；每一步都服务于阅读、辨识和行动。

## 结论先行

首页最适合做成一间有自然光的当代阅读室：暖白为“墙面”，深靛蓝为一面承载首篇文章的“主墙”，低饱和石墨色用于正文和结构，克制的矿物黄只承担导视与可点击重点。色彩不是三种并列的装饰，而是有面积纪律：浅色约 70–80%、深色约 15–25%、强调色不超过 5–10%。

空间应该由内容层级，而不是特效，制造记忆点：进入页面先看见一句清晰的立场，再自然抵达一张可读的专题文章卡，最后到达整齐、可扫读的项目“书架”。首屏不重复姓名或杭州；身份只在全站固定的一个位置出现。

## 研究依据与可落地规则

| 主题 | 有据可查的发现 | 对首页的含义 |
| --- | --- | --- |
| 信息与视觉顺序 | [WCAG 2.2 — 1.3.2 Meaningful Sequence](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html) 要求：当内容的呈现顺序会影响意义时，程序可确定的阅读顺序也必须保留意义。 | 先在 DOM 中放“定位 → 首篇文章 → 项目”，再用 CSS 排版；不能只靠绝对定位把阅读顺序打乱。装饰编号、网格线、背景字不应抢到正文之前。 |
| 标题作为房间门牌 | [WCAG 2.2 — 2.4.6 Headings and Labels](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) 指出标题和标签应描述主题或目的。 | 用一个明确的 H1 表达站点立场；“工程笔记”“开源项目”是可理解的 H2，不把 `01 / 02` 单独当作标题。编号只作为次级导视。 |
| 文本对比 | [WCAG 2.2 — 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 对普通文字要求至少 **4.5:1**，大号文字至少 **3:1**；[1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 对交互组件和关键图形也要求至少 **3:1**。 | 暖白背景上的石墨正文按 4.5:1 校验；黄色不直接承载小号正文，改为色块、下划线或大号标签，并为按钮、焦点环和卡片边缘校验 3:1。深蓝舞台上的白字同样单独校验。 |
| 用户可调文字 | [WCAG 2.2 — 1.4.12 Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) 规定当用户把行高调至 1.5 倍字号、段落间距调至 2 倍字号、字距调至 0.12 倍、词距调至 0.16 倍时，内容或功能不得丢失。 | 不把文案锁死在固定高度，也不要用 `overflow: hidden` 截掉说明；专题卡与项目行留出垂直弹性。中文正文也应使用舒展的行高（可从 1.65–1.8 开始实测）。 |
| 小屏是同一间房 | [WCAG 2.2 — 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 要求在等效于 320 CSS 像素宽时，内容可以重排而不丢失信息或功能，且不需双向滚动（特定二维内容例外）。 | 深蓝“主墙”在手机上从左右分栏变为上下顺序；项目行允许摘要下移，但链接、年份、状态仍完整可点。不能靠缩放整张桌面布局来保住一行。 |
| 可控的阅读行长 | [WCAG 2.2 — 1.4.8 Visual Presentation](https://www.w3.org/TR/WCAG22/#visual-presentation) 的 AAA 阅读建议包括：一行不超过 80 个字符或字形（CJK 不超过 40）、行距至少为 1.5 倍，并且不要两端对齐。 | 这不是 AA 合规门槛，却是技术文章值得采用的高质量目标：正文/长摘要做成宽度有限的“阅读桌”（可先以约 34–40 个中文字符实测），左对齐、约 1.75–1.9 行高；编号与元数据成为边桌而非第二段正文。 |
| 动效不应占用注意力 | [WCAG 2.2 — 2.2.2 Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) 要求对于自动开始、持续超过 5 秒、与其它内容同时展示的移动/闪烁/滚动信息，用户可暂停、停止或隐藏（有必要的活动除外）。 | 首屏可以有极慢的光影或细颗粒，不能有不停移动的“数据流”抢阅读；悬停动效只反馈交互。实现时尊重 `prefers-reduced-motion`，并给自动内容提供静态状态。 |
| 字体层级 | [Google Fonts Knowledge — Variable fonts](https://fonts.google.com/knowledge/glossary/variable_font) 说明可变字体在一个字体文件中提供一组样式范围。 | 选一套中文字形可靠的字体家族，通过字号、字重、间距建立层级，而不是堆叠多种字体制造“设计感”；文章舞台和目录仍属于同一间房。 |

## 空间脚本（设计综合，而非另一个功能区）

1. **门厅 / 入口（Hero）**：留出白，只有一条身份线、一个立场 H1 和很短的引导。它的任务是“定调”，不是塞进履历、城市故事和所有项目。
2. **主墙 / 焦点（Featured note）**：一整块深靛蓝形成视线停靠点；标题、摘要、文章元信息在其中有明确层级。它像挂在墙上的大幅作品，但仍可完整阅读、可点击、可键盘访问。
3. **阅读桌 / 细节（Article trace）**：在主墙里或其下只放一个小的工程痕迹，例如版本、时间、技术标签、简短流程。避免把“仪表盘”误当成内容；细节应支撑文章，而非制造噪声。
4. **书架 / 项目（Projects）**：把项目变成有稳定列宽和基线的目录。每项先是名称和一句作用，再是技术 / 链接；使用边线和间距组织，不用每项一张浮夸的卡。
5. **窗光 / 导视（Color & motion）**：黄色只标记“下一步”和重要状态，深蓝只聚焦一处；其余区域让暖白和石墨安静工作。动效只像光线随鼠标或滚动轻微变化，默认不承担信息表达。

## 推荐的色彩语义（先通过对比测试再固化为 token）

| 角色 | 建议感觉 | 使用面积与任务 |
| --- | --- | --- |
| 墙面暖白 | 纸张、日光、停留 | 最大面积；正文阅读背景。避免纯白带来的刺眼与廉价“后台感”。 |
| 石墨蓝黑 | 墨色、书架、正文 | 正文、导航、分隔线；承担绝大多数信息。 |
| 深靛蓝 | 专题主墙、夜读氛围 | 只给首篇内容或关键区块，形成单一视觉锚点。 |
| 矿物黄 | 书签、门把手、注释笔 | 只用于链接状态、编号底色、极少量标签与焦点；避免作为小字前景。 |

用语义 token（如 `canvas`, `surface`, `ink`, `night`, `signal`, `line`, `focus-ring`）来实现，而不是按“蓝/黄”命名；这也符合 [Material Design 3 的 color roles](https://m3.material.io/styles/color/roles) 对颜色角色（而非色相名称）的组织方式。这样深色舞台和浅色页面都能各自保持可读性。每一种前景/背景组合都应在实际字号与字重下测试，不以截图观感代替对比度测试。

## 交付前检查清单

- [ ] 同一页面的姓名 / 地点只出现一次；不要用大背景字再次复述身份。
- [ ] H1 只有一个，文章与项目标题描述清楚主题；键盘 Tab 顺序与眼睛阅读顺序一致。
- [ ] 普通文字 4.5:1、非文本交互线条和焦点 3:1；黄色没有承担小号正文。
- [ ] 在 320px 宽、200% 文字缩放和自定义文字间距下，内容不裁切、不横向滚动。
- [ ] `prefers-reduced-motion` 下没有持续的视觉运动；自动运行超过 5 秒的内容可停下。
- [ ] 桌面端首篇文章摘要的行长经过实测，保持舒适阅读而不是跟随容器无限变宽。

## 资料边界

WCAG 的 1.4.3、1.4.10、1.4.11 和 1.4.12 是可验证的基线；1.4.8 是 AAA 级阅读质量目标。所有宽度、字号与颜色仍应结合该站真实的中文字体、文章长度和浏览器实测调整。
